# Drifthold

An original real-time colony-building strategy game for Windows 11.

You are the Warden of a newly chartered mining Hold in the Shoal, a ring of
shattered rock circling the red dwarf Emberfall. Sink Bore Rigs into drifting
rocks, smelt Ore into Alloy, keep your colonists fed and breathing, research
your way to ships, claim more rocks, and break the rival Holds before they
break you. A Hold lives while it has a Keystone; the last Hold standing wins.

Everything you see and hear is generated by the game's own code: there are no
image or sound files.

## Playing

**Run it:** double-click `Drifthold.exe`. It is a single file with no
installer and nothing to install alongside it. Saves and settings are kept in
`%AppData%\Drifthold`.

**The first ten minutes**

1. Pick *Sunvane* on the **Power** tab and click a tile next to your Keystone.
2. Put a *Bore Rig* on or beside an Ore deposit (the Build list's
   *Show deposits* button highlights what you have surveyed; *Conduits* extend
   your reach), then a *Smelter*. Alloy is what almost everything is built from.
3. Add a *Habitat*, a *Greenhouse* and an *Aerator* as the colony grows, and a
   Bore Rig on Ice: colonists drink it, Greenhouses use it, and Crackers turn
   it into Fuel for your ships.
4. Build a *Laboratory* and choose a project in **Research**.
5. Follow the Directives in the top-left corner: they walk you from the first
   Sunvane to your first fleet. The in-game **Codex** (F1) explains every
   structure, ship and technology.

**Controls**

| | |
|---|---|
| Left click | select, place, press |
| Right click | cancel placing, deselect; on the belt map with a fleet selected: orders menu |
| Right-drag or W A S D / arrows | pan |
| Mouse wheel | zoom |
| Tab | surface view / belt map |
| Space, 1, 2, 3 | pause, normal, double, quadruple speed |
| R, F, E, H, L, F1 | Research, Fleets, Exchange, Holds, Log, Codex |
| G | show deposits |
| , and . | previous / next colony |
| Delete | demolish the selected structure |
| F5 | quick save |
| F11 or Alt+Enter | full screen |
| Esc | cancel, close, menu |

## Building from source

You need [Go](https://go.dev/dl/) 1.25 or newer. No C compiler is needed for
the Windows build.

On Windows:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1
```

From Linux or macOS (cross-compiling):

```sh
scripts/build-windows.sh 1.0.0   # dist/Drifthold.exe and a zip
```

To run the game on Linux for development you also need the X11, OpenGL and
ALSA headers (`libgl1-mesa-dev xorg-dev libasound2-dev` on Debian/Ubuntu), then
`go run ./cmd/drifthold`.

## Development

```
cmd/drifthold     the game
cmd/driftsim      headless runner: every Hold played by the rival AI
internal/model    all game data types and the content tables (structures, ships, research)
internal/sim      the rules: world generation, economy, construction, fleets, combat, research, market, events
internal/ai       the rival Holds' brains
internal/save     save files and settings
internal/app      the application: screens, panels, windows, input handling
internal/ui/kit   small immediate-mode widget toolkit
internal/gfx      drawing toolkit: canvas, text, theme, starfield
internal/art      procedural artwork: rocks, structures, ships, icons
internal/audio    synthesised sound effects and generative music
internal/input    input snapshots and scripted input playback
internal/uitest   headless harness for scripted runs with screenshots
internal/emblem   the logo, drawn in code
tools/winres      writes the Windows icon / manifest / version resource
docs/             design notes
```

* `go test ./...` runs everything, including a random-input test of the whole
  interface and a randomised soak test of the rules. The simulation is
  deterministic: the same seed and commands always give the same game.
* `go run ./cmd/driftsim -runs 10 -cycles 150 -quiet` plays AI-only games and
  prints how they went; `-seed N -every 10 -v` prints one game in detail. It is
  the tool for judging balance.
* `drifthold -script steps.json -out shots/ -new 42` plays scripted input and
  writes screenshots, with or without a real display (`xvfb-run` on Linux).
  The step format is described in `internal/input`.

Third-party components and their licences are listed in
`THIRD_PARTY_LICENSES.md`.
